## 지도 정합과 자세 변환

- 두 기준 JSON은 바이트 단위로 동일하다. SHA-256은 `39d757cabc5d04971af27d9fad5f6adf53e1818308dcf52eefd1b9d4f973f3c6b`다. 메인 기준 래스터와 별도 프로젝트의 `first.png`도 디코딩 후 2000×2000 BGR 전체 픽셀이 일치했다.
- `map_with_tags.png`는 5000×5000이다. 2000×2000으로 축소해 태그 종이를 제외하고 기준 래스터와 아핀 정합했다. 상관계수는 0.99983, 병진은 각 축 0.002 px 미만, 축 배율 차이는 각각 0.000002 미만이었다. 모델 좌표 변환은 항등이다. 원점은 남서쪽, +x 동쪽, +y 북쪽, +z 지도 위쪽이다. 태그 이미지의 픽셀 좌표는 `(2000x, 2000(2.5−y))`로 대응한다.
- Tag Family는 `tag36h11`, ID는 0–38이다. 검은 정사각형의 코너는 마커 자체의 좌상·우상·우하·좌하 순서다. 기준 코너로 정면 보정한 원본에서 39개 ID를 모두 확인했다. 정면 보정 없이 원본 타일에서 검출된 29개의 코너 오차는 RMS 0.73 px, 최대 0.97 px였다. 두 검사는 배치 확인에 사용했다.
- ID 0–27의 종이는 건물 도형 안쪽을 가린다. ID 28–38은 도로·건물 사이 빈 공간에 놓인다. 800 px/m로 래스터화한 검증에서 후자의 도로 겹침은 약 0.00012 모델 m²였다. 검출한 태그는 투시 변환으로 흰 종이까지 포함해 기존 정합 점수에서 제외한다. 인식에 실패하거나 일부가 잘린 태그는 마스크가 빠질 수 있다.
- 모델에서 검은 변은 40 mm, 종이는 50 mm다. `s = 실측 출력물 폭 / 2.5 m`를 사용해 모델상의 평면 점을 인쇄상의 물리 거리로 바꾼다. PnP는 중심을 옮긴 인쇄 좌표에서 `X_cam = R X_print + t`를 계산한다. `−Rᵀt`의 XY를 `s`로 나누고 모델 원점을 복원해 지도 XY를 얻는다. 이 방식으로 카메라 광학 중심을 지도에 수직 투영한다. `span`은 보정된 영상 가로 중심선을 지도 평면에 투영한 폭이다. [OpenCV PnP 좌표계](https://docs.opencv.org/4.x/d5/d1f/calib3d_solvePnP.html)
- 카메라 축은 오른쪽, 아래, 전방이다. 설정된 이미지 회전·반전을 반영한 상단 방향을 지도에 투영해 북쪽 기준 반시계 yaw로 변환한다. 기존 별도 프로젝트의 heading은 북쪽 기준 시계 방향이다. 태그 데이터의 `yaw_deg`는 동쪽 기준 종이의 회전이다. 카메라와 기체 사이의 별도 외부 보정은 적용하지 않았다.

## 관측 채택과 재탐색

- 해상도에 맞는 실측 카메라 보정값과 인쇄 폭, 유효한 마커 ID·코너가 필요하다. 원본 영상에서 14 px 미만의 변, 영상 경계에 붙은 태그, 잘못된 Family·ID, 중복 ID와 과도한 원근을 검사한다. OpenCV 검출 API의 출력에는 태그별 decision margin·Hamming 점수가 제공되지 않는다.
- 한 개 또는 여러 태그의 코너를 함께 사용한다. 여러 태그가 충돌하면 태그 쌍으로 후보 자세를 구해 다수의 태그가 지지하는 해를 찾는다. 재투영 RMS·카메라 방향·위치 공분산·평면 자세 모호성을 다시 검사한다. `AprilTagConfig`, `FilterConfig`, `TrackingConfig`에 실험용 초기 임계값과 불확실성을 정의했다.
- 지도 정합은 점수·후보 간 차이, 태그는 재투영 오차와 위치·yaw 불확실성을 보고한다. 두 관측은 프레임 ID와 시간이 같아야 한다. Mahalanobis 및 속도 게이트를 통과한 두 관측이 위치·yaw에서 일치할 때 covariance intersection으로 한 번만 필터를 갱신한다. 두 결과가 충돌하면 재투영을 통과한 다중 태그 합의를 선택할 수 있으며 단일 태그와 지도 결과가 모두 그럴듯하지만 상충하면 둘 다 거절한다.
- 지도 정합의 위치는 영상 중심이 가리키는 지도점이다. 채택 가능한 태그 자세가 있을 때 보정된 영상 중심과 카메라 수직 투영점 사이의 차이를 계산한다. 차이가 0.05 모델 m 이하이면 지도 관측을 카메라 중심으로 보정하고, 그보다 크면 태그 자세를 사용한다. 태그가 보이지 않는 경사 구간에서 기존 지도 정합의 수직 촬영 가정으로 인한 오차는 남는다.
- 태그 소실 시 지도 관측으로 추적하거나 새 절대 관측 없이 예측한다. 초기 태그가 없고 지도 정합도 실패하면 위치를 제공하지 않는다. 기존 추적이 있으면 위치 불확실성이 증가하고 허용 시간·불확실성 한계에서 위치 출력을 중단한다. 멀리 벗어난 태그 후보는 추적 손실 상태에서 두 개의 일관된 연속 관측을 받아 재초기화한다.

## 동일 프레임 세 모드 비교

320×240 합성 51장, OpenCV 스레드 1개, 지도 정합·태그 순차 실행으로 비교했다. `map`은 기존 태그 없는 정합 경로, `apriltag`는 태그만, `fusion`은 두 소스를 사용한다. 성공률은 전체 프레임 중 채택 관측의 위치 오차가 0.05 모델 m 이내이고 yaw 오차가 15° 이내인 비율이다. 오채택률은 채택 관측 중 이 기준을 벗어난 비율이다. RMSE와 yaw 평균에는 예측 위치를 포함하지 않았다. 처리 FPS는 평균 처리 시간의 역수다.

Fusion에서 태그 검출 평균은 11.13 ms, 검출 후 자세 계산은 5.74 ms, 지도 정합은 200.45 ms, 융합은 0.29 ms, 추적 갱신은 0.43 ms였다. 단계별 평균은 해당 단계가 실행된 프레임으로 계산했다. 이 세트에서는 지도 검색이 처리 지연의 대부분을 차지했다. Windows에서 단일 실행으로 측정해 절대 처리 시간은 실행 간 편차가 있다.

별도 프로젝트의 12장 합성 세트를 독립 프레임으로도 평가했다. 640×480에서 마커가 모두 들어온 프레임 8장 중 7장을 채택했고 위치 RMSE는 0.0045 m였다. 같은 프레임을 320×240으로 축소하면 3장을 채택했고 그 세 장의 RMSE는 0.0048 m였다. QVGA에서는 태그가 검출돼도 작은 코너가 거절되는 경우가 잦았다. 이 결과는 크기·가시성에 대한 별도 스트레스 검사이며 위 51장과 입력 구성이 다르다.

### 기존 XIAO 녹화 재생

`a4_stationary.avi`는 320×240의 실제 XIAO 녹화이며 위치·yaw 실측 정답이 없다. 기존 A4 색 설정을 사용했다. 처음 30장을 동일 순서로 처리했을 때 Map과 Fusion은 각각 29장 채택, 1장 예측으로 일치했다. 태그는 검출되지 않았으며 AprilTag 모드는 위치를 출력하지 않았다. 순차 처리 평균은 Map 271.8 ms, Fusion 371.8 ms였고 Fusion의 태그 검출 평균은 5.71 ms였다. 8초 예약 재생에서 각 모드에 45장이 공급됐다. 재생 중 어떤 프레임이 선택되는지는 처리 시간에 따라 달라진다.

| 모드 | 공급 FPS | 유효 처리 FPS | Frame Age 평균 / P95 (ms) | Receive-to-Result 평균 / P95 (ms) |
| --- | ---: | ---: | ---: | ---: |
| Map | 5.62 | 2.75 | 22.6 / 162.0 | 300.3 / 979.8 |
| AprilTag | 5.61 | 5.61 | 0.20 / 0.36 | 2.43 / 6.39 |
| Fusion | 5.62 | 4.99 | 7.85 / 47.32 | 87.17 / 219.91 |

이 측정의 공급 FPS는 저장된 타임스탬프에 따른 재생 속도다. 태그를 부착한 실물 지도의 위치 RMSE와 라이브 XIAO 처리량은 측정하지 못했다. 이전 부팅 로그의 스트림 주소에서 프레임 수신을 요청했으나 연결이 시간 초과됐다. 실물 검증에는 현재 스트림 주소, 같은 영상 모드의 체커보드 보정 파일, 인쇄 폭과 태그 위치가 확인된 출력물이 필요하다.

### 자동 회귀와 실행 검증

변경 전 `unittest` 79개 중 78개가 샌드박스에서 통과했다. MJPEG 재연결 테스트의 로컬 소켓 연결은 Windows의 소켓 접근 거부로 막혔다. 루프백 연결을 허용한 환경에서 최종 `unittest` 92개가 모두 통과했다. 기존 건물·도로, 전역·지역 검색, 자동 축척, 조명·그림자, 칼만 필터, 최신 프레임 슬롯, GUI, 녹화·재생을 포함한다.

태그가 검출된 합성 영상을 AVI에 기록한 뒤 `main.py --video-file`로 타임스탬프 재생과 단계별 CSV를 확인했다. 해당 프레임에서 GUI 코너·중심·자세 축이 렌더링됐고 태그 오버레이와 조명 진단 전환, 위치 추정 모드 전환을 확인했다. PowerShell 실행 스크립트의 구문 검사와 CLI 도움말도 확인했다.
